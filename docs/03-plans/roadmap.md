# 路线图（2026-10-19 起草，待 Owner 确认）

原则：**先让工程可靠，再扩功能，最后做可信度与发布**。每个阶段结束打一个版本标签。

## 阶段 0：工程地基（v5.5，约 1–2 周）
目标：任何助手、任何新电脑都能一条命令装好、测试全绿、改动有门禁。
- TASK-0001 依赖锁定（mcp<2、spaCy 模型、llama 可选）
- TASK-0002 统一配置（.env 真正生效、端口/模型名一致）
- TASK-0003 仓库卫生（scratch 出库、LICENSE、分支收敛到 main）
- TASK-0004 CI（pytest + 前端 lint/build）

## 阶段 1：结构重构（v5.6，约 2–3 周）
目标：降低重复，让新增诊断维度只需改一处。
- TASK-0005 诊断流水线重构，定义 `SentenceResult` 契约
- TASK-0006 PPL 向量化（并建立性能基准）
- TASK-0007 前端组件化（与 `SentenceResult` 类型对齐）
- TASK-0008 MCP 拆分 + `ToolResult` 模型
- TASK-0009 会话 TTL 与本机安全默认值

## 阶段 2：补齐 Web 能力（v5.7）
目标：MCP 已有、Web 缺失的能力进 UI（每项先写 REQ）。
- 报告导出按钮（Markdown/JSON）
- ВАК/ГОСТ 合规审计面板
- 改写建议（逐句"采纳/忽略"，不自动改原文）
- TASK-0011：其余 501 接口立项或删除

## 阶段 3：可信度（v6.0）
目标：每个阈值和宣称都有评测支撑，可写进论文/对外介绍。
- TASK-0010 评测集与评测脚本；阈值重新校准
- 误报样例库与回归测试（防止规则改动导致误报回升）
- README 量化表述与隐私表述按评测和实际行为修订

## 阶段 4：分发（视需要）
- 打包为可 `pip install` 的包或桌面应用；MCP 以 `uvx`/入口脚本形式安装
- 规则库版本化（与上游 PhD Thesis Butler Skill 同步机制）
