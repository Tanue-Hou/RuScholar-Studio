# 设计规约 - 3句分批并发、诊断说明精炼与双向滚动修复

本文档详细描述了 PhD Thesis Butler 学术风格诊断工具在并发提速、诊断内容精简以及页面跳转交互三大核心维度的设计方案。

## 1. 设计背景与问题分析

在用户的使用体验与系统测试中，发现了以下三个主要痛点：
1. **速度慢与限流风险的冲突**：完全串行处理长论文耗时过长，但如果将整篇论文的所有句子全部发起并发（例如50句以上），会瞬间触发 DeepSeek 等云端大模型 API 的 429 频控报错或 urllib 连接超时。
2. **分析诊断过于冗长**：模型生成的 `explanation_zh` 和 `<think>` 推理内容经常长篇大论，导致右侧的“风格透视（Sentence Inspector）”卡片被无限拉长，影响整体界面的高级感，且用户难以抓到关键的改写重点。
3. **交互跳转失效/体验不连贯**：
   * 点击右侧警报卡片，左侧文档正文有时未能正确滚动到对应句子上（由于 DOM 频繁批量重绘导致 Ref 尚未写完的渲染竞态）。
   * 点击左侧正文中的句子时，虽然右侧顶部的“风格透视”面板更新了，但如果右侧滚动条已经滚到下方，用户必须手动滚回顶部才能看到结果，体验支离破碎。

---

## 2. 方案设计

### 2.1 3句顺序分批并发 (Batch Sequence Concurrency)
为了在速度与 API 安全性之间取得完美平衡，我们采用 **3句一组的分批并发** 策略。

* **分批并发机制**：
  将正文的句子数组以 `batch_size = 3` 进行分块。对于每一块，使用 `asyncio.gather(*tasks)` 并发分发 3 个评估任务，其中：
  * **本地模型**：虽然 `llama_cpp` 内部因硬件原因必须通过 `model_lock` 进行物理串行推理，但规则过滤、相似度计算、预处理等可以实现线程级并发；
  * **云端模型**：3 个 API 请求通过线程池（`asyncio.to_thread`）同时分发，既能实现 3 倍的物理提速，又绝不会触发 429 限频保护。
* **顺序产出保证**：
  由于使用 SSE 协议进行实时流式传输，必须在每一组 3 句话的并发全部完成后，严格按照句子的原始索引顺序输出至前端，以保证前端渲染的确定性与流畅度。

### 2.2 判断分析双重精简与截断守护
根据用户的最新明确指令：“思考可以变长，但是最终呈现出来的前端和判断分析要保持100字以内”。

1. **System Prompt 约束**：
   在 `llm_judge.py` 中，调整 System Prompt：
   * 允许思考过程（`<think>` 标签内容）自由展开，确保复杂推理的质量；
   * 强制规约 `explanation_zh`（中文解释）必须精准指出 Breach 规则和核心指标，**严格限制在 90 个汉字以内**。

### 2.2 精准字数限制与思维链对齐 (Concise Prompts in Chinese)
在保证大模型深度分析质量的前提下，精炼并压缩输出文字：
* **模型思考允许自由展开**：在 local 与 cloud 的推理提示词中，放开对 `<think>` 思维链的超短字数限制，允许大模型充分发挥其深度逻辑推理优势，确保修改意见和诊断分析的高质量。
* **风格诊断说明极致精简**：通过微调 `llm_judge.py` 中的 System Prompt（限制 `explanation_zh` 的字数在 80-90 字以内），要求模型用一两句话、不超过 90 个字直奔主题，点明具体的指标偏移或 PhD Thesis Butler 规则触碰，不产生多余的废话和臃肿的翻译腔，同时避免卡片过长破坏排版，且保障跳转体验。

### 2.3 双向滚动与渲染防抖
1. **左侧正文平滑滚动防抖**：
   在前端 `App.tsx` 的 `scrollToSentence` 中加入 50ms 的 `setTimeout` 防抖。这样可以等待 React 状态渲染及 DOM repaint 完毕后，再调用 `scrollIntoView({ behavior: 'smooth', block: 'center' })`，彻底解决 Ref 在渲染竞态下丢失的 Bug。
2. **右侧滚动条自动回顶**：
   新增 `rightColumnRef` 绑定右侧卡片面板容器。当用户在左侧点击句子触发 `setSelectedSentenceIndex` 时，自动调用：
   `rightColumnRef.current?.scrollTo({ top: 0, behavior: 'smooth' });`
   将右侧控制面板自动平滑滑回顶部，确保“风格透视”区域第一时间展现在用户视野正中。

## 3. 规约自审与可维护性
* **接口变更**：`main.py` 内部 SSE 生成器逻辑从 `for sentence in sentences` 升级为 `for batch in chunk(sentences, 3)`。对前端暴露的 `/api/diagnose` SSE 事件结构完全一致，无向下兼容性风险。
* **语言环境**：全部代码注释、中文提示词、文档均使用纯正学术中文呈现。
